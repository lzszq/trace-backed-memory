# 规范事件 v1

[English](event-v1.md) | **简体中文**

`tbm.event.v1` 是完整持久化事件账本的存储中立规范信封。它固定后续账本写入器、
reducer、重放、投影和适配器共同使用的字节与来源。本里程碑只定义事件契约：不追加
事件、不选择数据库、不运行 reducer、不授权调用方，也不注册具体事件类型族。

## 信封

每个事件都绑定：

- 可扩展的 `event_type`、由生产者维护的 `event_version` 以及带版本的
  `payload_schema`；
- 流身份、正数流版本、正数全局位置和精确的前一事件哈希；
- 由可信上下文提供的组织、租户、仓库、环境、主体、Agent 客户端、行为者和授权
  决策身份；
- 请求、幂等、关联和因果身份，以及请求摘要；
- 生产者身份/版本、分类、保留策略、结构化载荷和仅含描述信息的制品引用；
- 已知时的生产者发生时间、可信记录时间、载荷哈希，以及独立进行域分隔的事件哈希。

`event_id` 是稳定的逻辑标识；`event_sha256` 是完整无哈希信封的不可变完整性标识。
事件哈希为 `SHA-256("tbm.event.v1\\0" || canonical-json(unsigned-event))`。
载荷哈希使用相同的规范 JSON 编码，但不带该信封域前缀。规范 JSON 使用 UTF-8、
对象键排序、紧凑编码，并且只允许有限数值。

## 来源与时间

原生领域事件不能声称导入来源。导入事件或观察事件必须携带来源系统记录、证据质量
和观察时间。只有存在来源观察证据时，`occurred_at` 才能为 `null`；这样可以保留
不确定性，而不是捏造历史时间。`recorded_at` 始终必填，并且必须来自可信基础设施。
已知的发生时间和观察时间不能晚于记录时间，同一流的记录时间也不能倒退。

流中的首个事件使用 `stream_version = 1`，且不带前一哈希。之后的每个事件都必须
指向精确的父事件哈希，并将流版本递增一。父事件验证器还会固定流/作用域身份，要求
全局位置严格递增。事件账本必须以原子方式执行同样的规则；本契约本身不是并发控制。

## 载荷与制品

运行时解析器拒绝重复键，并把完整文档限制为 1 MiB、深度 32、10,000 个节点；
载荷必须是对象，限制为 512 KiB、深度 24、8,192 个节点。循环、非 JSON 值、
非有限数、未知信封字段以及常见的秘密承载元数据键都会被拒绝。

制品引用是排序、唯一、内容寻址的描述符，不包含制品字节。引用绑定媒体类型、大小、
分类、保留策略、受保护时的加密密钥身份以及可用性。事件分类不能低于其引用的制品。
制品授权和字节可用性仍由 Artifact Authority 负责。

## 信任与演进边界

外部 JSON 不能选择可信的组织、租户、仓库、环境、主体、客户端、行为者或授权决策
身份。写入器从已认证的 `EventTrustedContext` 构建事件，并在追加前再次核验相同身份
槽位。Schema 验证只提供结构预检；运行时代码必须重新计算两个哈希，并核验精确父
事件和可信上下文。

格式正确但未知的事件类型会被本信封有意保留。类型化注册表、各类型载荷验证器、兼容
声明、upcaster 以及 reducer 对未知类型的行为由
[事件类型注册表 v1](event-registry-v1.zh-CN.md) 定义。这个边界让基础信封保持可扩展，
同时不会虚假声称每个事件都已经能被 reducer 理解。

原子 append/read/verification/subscription 边界由
[Event Ledger Port v1](event-ledger-port-v1.zh-CN.md) 单独冻结。opt-in SQLite 与隔离
PostgreSQL 后端现已实现该端口，但不会改变 active authority-graph composition。
